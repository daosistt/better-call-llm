# Better call LLM

Локальное Linux-приложение, которое слушает разговор, выделяет условие задачи
и показывает решение в браузере. Поддерживает математические, статистические
и продуктовые вопросы — от производной до выбора метрик и дизайна эксперимента.

Речь распознаётся на CPU через faster-whisper и Silero VAD. Извлечение условия
и автоматическое решение выполняет Codex CLI; для ручного решения также доступен
OpenAI API. Исходное аудио в облако не отправляется.

## Возможности

- Одновременный захват микрофона и системного звука через PipeWire/PulseAudio.
- Русская речь с метками «Ты» и «Собеседник».
- Накопление условия из нескольких реплик и автоматический запуск решения.
- Учёт исправлений, защита от устаревших ответов и лишних повторных запросов.
- До двух трактовок неоднозначного условия с явными допущениями.
- Решения с LaTeX, ручное редактирование и повторный запуск.
- Общий разговор и результаты на ноутбуке и телефоне в одной локальной сети.

Приложение находится в активной разработке. История хранится только в памяти;
регистрации и базы данных нет. Ответы модели необходимо проверять.

## Требования

- Linux и Python 3.11+.
- [uv](https://docs.astral.sh/uv/) для управления окружением и зависимостями.
- Работающий PulseAudio или PipeWire с совместимостью PulseAudio; команды
  `pactl` и `parec` должны быть доступны в `PATH`.
- Codex CLI в `PATH`, поддерживающий `exec --ephemeral`, `--json` и
  `--output-schema`. Вход: `codex login` под тем же пользователем, который
  запускает сервер. Подробнее: [документация Codex CLI](https://learn.chatgpt.com/docs/non-interactive-mode).
- Интернет для первой загрузки ASR-модели и обращения к Codex/OpenAI API.

GPU не требуется. Целевая конфигурация — Intel Core i5-13500H и 16 ГБ RAM.
Для разговора рекомендуются наушники: полноценного эхоподавления пока нет.

## Быстрый старт

Все команды выполняются из корня репозитория.

### 1. Установить зависимости

```bash
uv sync --locked
```

Команда создаёт отдельное окружение проекта `.venv` и устанавливает версии
из `uv.lock`.

### 2. Подготовить настройки и вход в Codex

```bash
cp .env.example .env
codex login
```

Для сценария с Codex CLI ключ OpenAI API не нужен: войдите в CLI через ChatGPT,
чтобы использовать доступные лимиты аккаунта. В `.env` можно оставить `ASR_MODEL=base` и остальные
значения по умолчанию. Для ручного решателя через API заполните `OPENAI_API_KEY`.

Автоматическое извлечение условия использует Codex даже при выборе OpenAI API
для ручного решения. Поддержка API здесь не заменяет необходимость Codex CLI
в автоматическом сценарии.

### 3. Загрузить модель распознавания

Веб-приложение использует только локальный кеш модели. Для первой загрузки `base`:

```bash
uv run --no-sync python -c "from faster_whisper import WhisperModel; WhisperModel('base', device='cpu', compute_type='int8', cpu_threads=4)"
```

Скачиваются только веса модели, обычно в `~/.cache/huggingface`.
Для `ASR_MODEL=small` замените `'base'` на `'small'` в этой команде.

### 4. Запустить приложение

```bash
uv run --no-sync streamlit run app.py
```

Откройте [http://127.0.0.1:8501](http://127.0.0.1:8501).
Остановка сервера — `Ctrl+C` в терминале.

## Использование

1. Подключите наушники. В приложении звонка выберите нужный микрофон и выход.
2. В Better call LLM откройте «Аудиоустройства и согласие»: выберите тот же
   микрофон и монитор выхода на наушники. Подтвердите согласие участников.
3. Включите авторешение и нажмите «Начать прослушивание».
4. Произнесите условие. Реплики появятся в «Расшифровке разговора», выделенная
   задача — в карточке «Условие», ответ — в карточке «Решение».
5. Для правки нажмите «Исправить условие», отредактируйте текст и запустите
   «Решить» или «Решить заново».

Ручная правка выключает авторешение. Для возвращения в автоматический режим
включите его явно. Прослушивание продолжается во время анализа и решения.
При пропуске аудио приложение покажет предупреждение: начните новый контекст
и повторите условие.

Для задачи без звонка используйте «Ручной ввод и повторное решение».
Загрузка записи, ввод тестовых реплик и техническая диагностика находятся
в разделе «Дополнительно». Загруженный аудиофайл ограничен 20 МБ.

### Доступ с телефона

```bash
uv run --no-sync streamlit run app.py --server.address 0.0.0.0
```

В той же Wi-Fi сети откройте `http://<IP_ноутбука>:8501`. Адрес Wi-Fi-интерфейса
можно посмотреть через `ip -4 -br address`; не используйте адрес VPN или Docker.
Если включён VPN на телефоне, разрешите в нём прямой доступ к локальной сети.

Все вкладки одного сервера видят общие разговор, задачу и ответ. Черновик ручного
редактора остаётся локальным для вкладки. Захват всегда выполняется на ноутбуке.
**Закрытие вкладки не останавливает прослушивание** — нажмите кнопку остановки
или завершите сервер.

По умолчанию сервер доступен только на localhost. При привязке к `0.0.0.0`
он доступен в локальной сети без авторизации; используйте доверенную сеть.

## Конфигурация

Настройки читаются из `.env` в корне репозитория; переменные окружения имеют приоритет.
После изменения настроек перезапустите сервер.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `ASR_MODEL` | `base` | Модель faster-whisper: `base` или `small` |
| `OPENAI_API_KEY` | Пусто | Ключ для ручного решателя через OpenAI API |
| `OPENAI_MODEL` | `gpt-5-mini` | Модель ручного API-решателя |
| `EXTRACTOR_PAUSE_SECONDS` | `3` | Пауза после новой реплики перед анализом |
| `EXTRACTOR_MAX_SECONDS` | `15` | Максимальное накопление реплик между проверками |
| `TASK_STABILITY_SECONDS` | `3` | Дополнительное ожидание перед авторешением |
| `AUDIO_BUFFER_SECONDS` | `5` | Ёмкость очереди PCM каждого источника |
| `ASR_QUEUE_SECONDS` | `48` | Бюджет очереди речевых фрагментов |
| `SPEECH_FRAGMENT_SECONDS` | `16` | Максимальная длина речевого фрагмента |
| `SPEECH_SILENCE_SECONDS` | `2.5` | Пауза для завершения речевого фрагмента |

Проверки не выполняются без новых реплик. Одновременно работает один запрос
экстрактора: если он длится дольше максимального интервала, следующая проверка
ждёт его завершения. При непрерывной речи фрагменты могут разделяться на границе
максимальной длины.

Для неторопливой речи начальные настройки — пауза 2,5 с и фрагмент до 16 с.
Короткие паузы остаются внутри фрагмента; более длинные завершают его.
Увеличение паузы даёт ASR больше контекста, но задерживает появление текста.
Это стартовые значения, качество и задержку на живой речи нужно проверить.
`EXTRACTOR_PAUSE_SECONDS` управляет анализом уже распознанного текста,
а не разбиением аудио. Для применения настроек перезапустите сервер.

`small` требует больше CPU и памяти. Для обеих моделей используется CPU INT8
с четырьмя вычислительными потоками; более крупная модель не гарантирует
улучшения на каждой записи. Модель загружается один раз на процесс сервера.

В «Настройках решателя» выбирается только **ручной** backend. Авторешение всегда
использует Codex CLI. CLI-ответ появляется целиком; OpenAI API поддерживает
streaming. Модель API должна поддерживать Responses API и `reasoning.effort=medium`.
Вызовы CLI не загружают пользовательский `config.toml` и используют модель
Codex по умолчанию.

## Обработка данных

- Аудио обрабатывается локально и временно буферизуется в RAM.
- В Codex или OpenAI API отправляется текст задачи и необходимый контекст.
  Эти обращения расходуют лимиты Codex или оплачиваемые API-кредиты.
- Выключение авторешения не отключает экстрактор: при прослушивании он продолжает
  отправлять новые реплики в Codex. Чтобы прекратить обработку, остановите прослушивание.
- Приложение не создаёт аудиозаписей, файлов транскриптов или базы истории.
  Перезапуск сервера удаляет состояние из памяти.
- `.env` содержит секреты и не должен попадать в Git. В репозитории хранится
  только `.env.example` без ключей.

Codex запускается с `--ephemeral`, API — с `store=False`. Эти параметры
не означают полного отсутствия журналов или обработки данных у провайдера.

## Проверки

Автоматические тесты не обращаются к Codex/API, не скачивают модели и не требуют
микрофона:

```bash
uv run --no-sync python -m unittest discover -s tests -v
```

GitHub Actions запускает эти тесты на каждом push и pull request: Ubuntu,
Python 3.14, зависимости из `uv.lock`. Секреты для CI не требуются.
Workflow находится в [`.github/workflows/ci.yml`](.github/workflows/ci.yml).

Дополнительные проверки запускаются отдельно:

| Команда | Что проверяет | Внешние обращения |
| --- | --- | --- |
| `python -m checks.check_dialogue` | Извлечение задачи из пяти синтетических реплик | Пять вызовов Codex |
| `python -m checks.compare_asr --model base запись.wav` | Текст, время и память выбранной ASR-модели | Только загрузка весов при `--download` |
| `python -m checks.check_stability --audio запись1.wav запись2.wav --seconds 60` | Два потока с настоящими VAD/ASR и заглушками LLM | Нет; нужна модель в кеше |

Запускайте их через `uv run --no-sync` перед указанной командой. Аудиопримеры
не входят в репозиторий: используйте свои записи с согласия участников.
`src.transcribe` также позволяет распознать один файл:

```bash
uv run --no-sync python -m src.transcribe /путь/к/задаче.wav --model base --offline
```

```text
app.py                         # Точка входа Streamlit

├── ui.py                      # Веб-интерфейс

├── live_speech.py             # Очереди, VAD и речевые фрагменты

├── conversation.py            # Контекст и извлечение вопроса
├── codex_backend.py           # Codex CLI
├── solver.py                  # Потоковый OpenAI API
├── config.py                  # Настройки из .env и окружения
├── prompt_loader.py           # Чтение промптов
├── transcribe.py              # Распознавание отдельного файла
└── schemas/extractor.schema.json

├── solver.md                  # Общий промпт решателя
└── extractor.md               # Промпт выделения вопроса

```

Команды запуска и тестов выполняются из корня репозитория.
Запуск Streamlit остался прежним: `uv run --no-sync streamlit run app.py`.

## Настройка промптов

Сейчас активен универсальный промпт для математических, статистических,
аналитических и продуктовых задач. Его копия —
[`prompts/solver.general.md`](prompts/solver.general.md).
Промпт для квантовой физики сохранён в
[`prompts/solver.quantum.md`](prompts/solver.quantum.md). Чтобы включить его:

```bash
cp prompts/solver.quantum.md prompts/solver.md
```

Вернуться к универсальному промпту:

```bash
cp prompts/solver.general.md prompts/solver.md
```

Редактируйте [промпт решателя](prompts/solver.md), чтобы
изменить тематику, стиль и глубину ответа. Он общий для Codex CLI и OpenAI API,
включая автоматические решения. Файл читается перед каждым запросом: сохраните
правки и запустите новое решение. Уже выполняющийся запрос использует прежний текст.

[Промпт экстрактора](prompts/extractor.md) определяет, какой
вопрос выделять из разговора и когда считать его полным. Если меняете тематику
разговора, учитывайте и этот файл. Сохраните требования к полям JSON и полноте
условия: код проверяет ответ по схеме.

Текст задачи и технические правила передачи данных добавляются отдельно в коде.
Промпты храните без ключей и других секретов; они входят в репозиторий.

## Ограничения

- Официальная целевая платформа — Linux. Захват на Windows/macOS не реализован.
- Метки говорящих определяются источником звука; это не диаризация голосов.
  Монитор выхода захватывает все звуки наушников, включая уведомления.
- Распознавание, полнота условия и решения могут быть ошибочными. При неоднозначности
  модель может предложить до двух вариантов с явно указанными допущениями.
- Длительный двухчасовой живой прогон ещё не выполнен. Тесты с повтором файлов
  не заменяют проверку настоящего звонка, Bluetooth и сетевых сбоев.
