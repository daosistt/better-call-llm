# Math Copilot

Текущий шаг: текстовая задача → Codex CLI или OpenAI API → решение с LaTeX
(streaming доступен в варианте с API).
В интерфейсе можно загрузить короткий аудиофайл и распознать его локально.
Доступны захват двух потоков звонка, локальное распознавание с метками говорящих
и автоматическая передача реплик экстрактору и решателю.

### Экстрактор задач и Codex CLI

Нужен установленный `codex` с поддержкой `exec --ephemeral`, доступный в PATH
процесса Streamlit. Выполнить `codex login` под пользователем, запускающим
приложение. Для CLI используется вход Codex, а не `OPENAI_API_KEY` из `.env`.
Модель выбирается Codex по умолчанию; пользовательский `config.toml` при этих
запросах не загружается. Ручной решатель выбирается в списке «Решатель»:
Codex CLI либо существующий OpenAI API. У CLI ответ пока появляется целиком,
у API сохраняется streaming.

Карточка «Условие» показывает результат выделения задачи из живого потока Whisper.
Для отдельной проверки открыть «Дополнительно → Текстовые реплики», выбрать
говорящего и последовательно добавлять фразы.
Это уже настоящие запросы к Codex, расходующие доступные лимиты. Например:
«Найдите производную функции», затем «икс в квадрате», затем «нет, икс в кубе».
Экстрактор возвращает условие, формулы, полноту и неоднозначности. После ошибки
он не повторяет запрос бесконечно: новая реплика запускает следующую попытку.

Планирование событийное: новые реплики объединяются до паузы в 3 секунды;
при непрерывных репликах проверка запускается через 15 секунд. Одновременно
выполняется только одна проверка. Реплики, поступившие во время неё, остаются
в контексте для следующей проверки; устаревший результат не принимается.
Если проверка длится больше 15 секунд, этот интервал не гарантирует частоту
ответов — следующая проверка начнётся только после завершения предыдущей.
Без нового текста запросов нет. Контекст ограничен 8000 символами и 40 репликами,
одна реплика — 2000 символов; предыдущее извлечённое условие передаётся отдельно.

Кнопка «Авторешение: выключено» разрешает запуск готовых условий
через Codex, независимо от выбора ручного решателя. Условие должно допускать
содержательное решение, а после принятия результата ещё 3 секунды не должно быть
новых реплик. Повторное неизменившееся условие не решается заново автоматически.
Содержательное уточнение делает старое решение неактуальным. Ручное редактирование
условия и остановка решения выключают автоматический режим; включить его снова
нужно явно. Извлечённое условие показывается отдельно и не затирает редактор.

Неточная формулировка и неоднозначности больше не требуют обязательного уточнения:
экстрактор явно описывает предположения и передаёт их вместе с условием решателю.
Решатель показывает свою интерпретацию; при двух правдоподобных прочтениях даёт
до двух вариантов условия и отдельное решение каждого. Неоднозначности видны
рядом с условием, а их изменение обновляет версию запроса. Отсутствующие числа
не придумываются: по возможности ответ даётся с параметрами. Если ещё нет самого
объекта задачи или вопроса, экстрактор продолжает накапливать реплики.

Поддерживаются также аналитические и продуктовые вопросы без формул и чисел.
Экстрактор сохраняет исходный запрос (например, как проверить эффективность
промоакции), а решатель сначала предлагает метод и практический план, а не
обязательную математическую модель. Для экспериментальных вопросов он рассматривает
уместность A/B-теста, метрики, группы и правило принятия решения. Математические
задачи по-прежнему получают полноценное решение с формулами.

Интервалы задаются в `.env` через `EXTRACTOR_PAUSE_SECONDS`,
`EXTRACTOR_MAX_SECONDS`, `TASK_STABILITY_SECONDS`; значения по умолчанию — 3, 15, 3.
После изменения интервалов перезапустить сервер (обработчик кешируется на процесс сервера).

CLI получает только текст через stdin и возвращает события JSONL через stdout.
Для результата экстрактора используется `extractor.schema.json`. Сессия запускается
с `--ephemeral` в пустом временном каталоге, без файлов транскрипции, истории или
решения. Запрос ограничен 180 секундами и 2 МБ вывода; отмена завершает группу
процессов. Это облачная обработка текста в Codex, а не локальная LLM.

Проверены настоящие вызовы экстрактора и решателя на синтетическом условии производной;
качество на длинном разговоре ещё не проверено. Потоковый VAD/ASR проверен
на предоставленном аудиофайле, подаваемом блоками по 100 мс, без потерь.
Живой разговор и двухчасовой прогон после этой интеграции ещё не проверены. Основа интеграции:
[официальная документация Codex CLI](https://learn.chatgpt.com/docs/non-interactive-mode).

### Проверка захвата звонка

Нужны системные команды `pactl` и `parec` (PulseAudio или совместимый сервер
PipeWire). В верхней панели «Аудиоустройства и согласие» выбрать встроенный микрофон ноутбука
для своего голоса и монитор выхода Bluetooth-наушников для голоса собеседника.
В приложении звонка выбрать тот же микрофон и выход. После подключения или смены
наушников нажать «Обновить устройства» при остановленном захвате.

Подтвердить согласие участников и нажать «Начать прослушивание». При речи должен
двигаться индикатор микрофона, при воспроизведении звука в наушниках — второй
индикатор. Монитор захватывает все звуки выбранного выхода, включая уведомления.
Захват выполняется на ноутбуке, даже если интерфейс открыт с телефона.
Для полного сценария включить авторешение, затем начать захват.
Распознанные реплики появятся с метками «Ты» и «Собеседник»
и временем относительно начала захвата в сворачиваемой «Расшифровке разговора». Без автоматического решения экстрактор
всё равно анализирует реплики через Codex; это расходует его лимиты.
«Остановить прослушивание», явное снятие согласия или остановка сервера останавливают потоки
и автоматический решатель. На остановке незавершённая речевая фраза отбрасывается.

Два процесса `parec` читаются независимо в общем asyncio loop сервера:
mono PCM s16le, 16 кГц, блоки 100 мс. Чтение не ждёт VAD, ASR или LLM.
Индикатор показывает RMS на шкале от −60 до 0 dBFS. Счётчики блоков подтверждают
поступление данных даже во время тишины. При ошибке одного потока второй
останавливается; процессы завершаются через terminate с резервным kill.

Очередь каждого источника вмещает 5 секунд PCM. Silero VAD раз в 0,5 секунды
анализирует ограниченное окно, отделяет речь после примерно 600 мс тишины и
ограничивает фрагмент 12 секундами (при непрерывной речи возможен разрез слова).
Ожидают ASR не более четырёх фрагментов по 12 секунд. Один потребитель Whisper
обрабатывает оба источника последовательно. Общая модель также используется
для загруженных файлов; вычисления выполняются через `asyncio.to_thread`.
Результаты сортируются по времени начала в пределах последних 50 реплик UI;
в экстрактор передаются также источник и временные метки. При перекрывающейся
речи завершившаяся короткая реплика может распознаться раньше длинной.

Буферы настраиваются в `.env`: `AUDIO_BUFFER_SECONDS=5`, `ASR_QUEUE_SECONDS=48`,
`SPEECH_FRAGMENT_SECONDS=12`. Ёмкость очереди фрагментов равна целой части
отношения ASR_QUEUE_SECONDS / SPEECH_FRAGMENT_SECONDS (не меньше 1).
При переполнении удаляется самый старый ожидающий блок или фрагмент, растут
счётчики потерь в «Дополнительно → Диагностика»; на основном экране появляется предупреждение. Разрыв последовательности сбрасывает VAD-буфер
соответствующего источника. Автоматическое решение и извлечение приостанавливаются;
нужно нажать «Начать новый контекст», повторить условие и снова разрешить
автоматическое решение. Сброс удаляет очереди и не допускает старый результат
уже выполнявшегося ASR в новый контекст. Аудио и история на диск не записываются.

Зависимости проекта добавляем через `uv add`. Для общего окружения используем
`--no-sync`, чтобы не удалять его посторонние пакеты. Эта команда обновляет
`pyproject.toml` и `uv.lock`, но сама пакеты не устанавливает.

Добавление зависимости с установкой в используемое общее окружение:

```bash
UV_PROJECT_ENVIRONMENT=/home/user/vscode/python/venv/.venv uv add имя-пакета
```

Скопировать `.env.example` в `.env` и заполнить `OPENAI_API_KEY` локально.
Не публиковать `.env` и не отправлять ключ в переписку. Переменная окружения
имеет приоритет над `.env`. В `OPENAI_MODEL` можно указать модель с поддержкой
Responses API, streaming и `reasoning.effort=medium`; по умолчанию `gpt-5-mini`
для первых проверок. Для сложных задач модель можно заменить через конфигурацию.
Запросы выполняются только после нажатия «Решить»/«Решить заново» и расходуют
API-кредиты. Наличие ключа само по себе не подтверждает доступ к API.

Запуск:

```bash
/home/user/vscode/python/venv/.venv/bin/python -m streamlit run app.py
```

Открыть http://127.0.0.1:8501. Ввести, например, «Найти производную x²» и нажать
«Решить». Дождаться ответа, исправить условие и нажать «Решить заново».
Новое решение заменяет предыдущее. Ответ модели необходимо проверять.

Запрос идёт в отдельном asyncio event loop; UI опрашивает безопасный снимок
состояния каждые 0,5 секунды. Один общий обработчик на процесс Streamlit
кешируется через `cache_resource(scope="global", on_release=...)`. Ноутбук,
телефон и другие вкладки одного сервера видят общий разговор, условие и решение
и управляют одним захватом. Подключение или закрытие вкладки не останавливает
обработчик; используйте кнопку остановки или завершите сервер. При штатном
выходе сервера ресурсы освобождает также обработчик `atexit`. Черновики ручного
редактора остаются локальными для вкладки, чтобы не затирать ввод другого клиента;
отправленные задачи и ответы общие.
Редактирование условия отменяет текущий запрос. Счётчик поколений не позволяет
позднему ответу отменённого запроса заменить актуальный ответ. Отмена закрывает
локальный поток и не гарантирует отмену уже выполненной сервером работы и её стоимости.
Частичный ответ при ошибке остаётся виден со статусом ошибки.

Общее состояние хранится только в памяти процесса сервера: обновление страницы
сохраняет текущую задачу и ответ, а перезапуск сервера сбрасывает их. Аудио и файлы истории не создаются. В Responses API передаётся
только условие и инструкция, с `store=False`; это отключает хранение Response
для последующего извлечения, но не является гарантией отсутствия всех серверных
логов провайдера.

Проверки без ключа, реальных API-запросов и аудиоустройств:

```bash
/home/user/vscode/python/venv/.venv/bin/python -m unittest discover -s tests -v
```

Использованы [OpenAI Python SDK](https://developers.openai.com/api/reference/python)
и [Responses streaming](https://developers.openai.com/api/docs/guides/streaming-responses).

### Проверка локального распознавания

Без API-кредитов: распознавание короткого готового аудиофайла на русском.
В веб-интерфейсе загрузить запись (до 20 МБ) в разделе «Дополнительно → Аудиофайл»
и нажать «Распознать». Текст и время обработки появятся в этом разделе.
Кнопка «Использовать как условие» явно заменяет текст в редакторе, после чего
его можно исправить и решить. Без нажатия этой кнопки ручные правки сохраняются.
Распознавание само не запускает платные API-запросы.

Файл передаётся декодеру в памяти через `BytesIO`, временные файлы не создаются.
ASR выполняется в потоке через `asyncio.to_thread` на общем обработчике
сервера; интерфейс и запрос решения продолжают работать. Дополнительные файлы
во время распознавания не ставятся в очередь. Модель общая для процесса,
лениво загружается один раз, её инференс сериализован блокировкой.
Остановка обработчика отменяет ожидание ASR; уже начатое CPU-вычисление завершается
в своём потоке, после чего освобождаются ресурсы. Время в UI включает ожидание
модели, её первую загрузку, декодирование, VAD и распознавание.

Веб-интерфейс использует только локальный кеш модели. Если он ещё не заполнен,
выполнить команду ниже один раз с доступом к интернету. CLI также доступен отдельно:

```bash
/home/user/vscode/python/venv/.venv/bin/python transcribe.py /путь/к/задаче.wav
```

Для первой проверки достаточно 10–30 секунд чёткой речи, например:
«Найдите производную функции икс в квадрате плюс три икс».
Можно использовать WAV, MP3, M4A и другие форматы, поддерживаемые PyAV.
Скрипт выводит текст и временные метки в терминал, не сохраняет аудио или
транскрипцию и не отправляет их в облако.

При первом запуске скачиваются веса `base` в кеш Hugging Face
(обычно `~/.cache/huggingface`); это файлы модели, а не история разговора.
После скачивания можно запретить доступ к сети:

```bash
/home/user/vscode/python/venv/.venv/bin/python transcribe.py /путь/к/задаче.wav --offline
```

Распознавание использует CPU INT8, четыре вычислительных потока, одного
работника и встроенный в faster-whisper Silero VAD. Один экземпляр
`SpeechRecognizer` переиспользует одну модель и последовательно обрабатывает
файлы. При будущей интеграции этот синхронный метод нужно вызывать вне
asyncio event loop через `asyncio.to_thread`.

Автоматические тесты подменяют ASR-модель и ничего не скачивают. Они проверяют
обвязку, но не качество русского распознавания: его нужно проверить на
аудиофайле отдельно. Запуск CLI загружает модель заново на каждый новый процесс;
в приложении один экземпляр переиспользуется в течение жизни процесса.

Основано на [официальной документации faster-whisper](https://github.com/SYSTRAN/faster-whisper).

PyAV ограничен версией ниже 19: faster-whisper 1.2.1 использует аргумент
`metadata_errors`, удалённый из `av.open` в PyAV 19. Совместимость декодера
проверяется отдельным тестом на синтетическом WAV без скачивания модели.
